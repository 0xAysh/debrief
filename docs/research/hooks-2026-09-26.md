# Host hooks research: Claude Code 2.1.283 and Codex CLI 0.148.0-alpha.21

Researched 2026-09-26. These findings come from docs and source and are **design input only**. Driven tests against the real binaries must pin the behavior.

## A. Claude Code 2.1.283

### A1. Stdin payloads

**Common fields** (CC-HOOKS "Common input fields"), **H**:
- `session_id`
- `prompt_id`: absent until the first user input; needs v2.1.196 or later
- `transcript_path`: "written asynchronously and may lag"
- `cwd`
- `scratchpad_dir`: v2.1.257 or later; may be absent
- `permission_mode`: `default|plan|acceptEdits|auto|dontAsk|bypassPermissions`. "Not all events receive this field."
- `effort`: `{level}`, only on tool-context events
- `hook_event_name`
- `agent_id` / `agent_type`: only inside a subagent or with `--agent`

**SessionStart** adds (**H**):
- `source`: `"startup"|"resume"|"clear"|"compact"|"fork"`. `fork` is a 5th value. Before v2.1.214, forks reported `"resume"`.
- `model`: optional; "can be omitted, for example after /clear"
- `agent_type`: with `--agent`
- `session_title`: optional
- On resume/fork (v2.1.251 or later): `seconds_since_last_response`, `context_tokens`, `prompt_cache_likely_expired`, `estimated_cache_write_usd`
- The doc example shows no `permission_mode` on SessionStart (**M**).

**UserPromptSubmit** adds `prompt` (**H**). The example includes `permission_mode`. Pasted text arrives expanded, possibly wrapped in `<pasted_content id=…>` lines (**H**).

**Stop** adds (**H**):
- `stop_hook_active`: "true when Claude Code is already continuing as a result of a stop hook"
- `last_assistant_message`
- `background_tasks`
- `session_crons`

There is an **8-consecutive-continuation cap**, overridable with the `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` env var (**H**). Stop "does not run if the stoppage occurred due to a user interrupt"; API errors fire `StopFailure` instead (**H**).

**PreToolUse** adds `tool_name`, `tool_input`, `tool_use_id` (**H**). For MCP tools it also adds `mcp_server: {name, source}` (v2.1.274 or later). `source` is `plugin|sdk|user|project|…`, and the docs say to "Base trust decisions on `source`" (**H**).

### A2. Output handling

**Stdout parsing** (**H**):
- Stdout is parsed as JSON only if it starts with `{` and ends with `}`. Otherwise it is plain text.
- Plain-text stdout on exit 0 is added to Claude's context **only** for `UserPromptSubmit`, `UserPromptExpansion`, `SessionStart`, `PostModelSwitch`. For other events it goes to the debug log.
- If stdout looks like JSON but fails to parse, the result is a non-blocking error and the text is **not** added as context. This applies since v2.1.248.

**Caps and exit codes** (**H**):
- `additionalContext`, `systemMessage`, and plain stdout are each capped at **10,000 chars**. Over the cap, the text is saved to a file and Claude gets a 2,000-char preview plus the path.
- Exit 2 blocks on blocking events, and JSON can't override it.
- Exit 1 without valid JSON is a **non-blocking error**.
- Stderr on exit 0 goes to the debug log only.

**`hookSpecificOutput.additionalContext`** (**H**):
- It is wrapped in a system reminder and does **not** appear as a chat message.
- SessionStart: added "at the start of the conversation, before the first prompt".
- UserPromptSubmit: added "alongside the submitted prompt". Neither channel produces a visible transcript entry.
- On `--resume`, the saved UserPromptSubmit text is replayed rather than re-run, so it goes stale. SessionStart re-runs with `source: "resume"`.

**SessionStart extras** (**H**):
- `initialUserMessage`, which only applies in `-p` mode
- `sessionTitle`
- `watchPaths`
- `reloadSkills`
- `CLAUDE_ENV_FILE` is available to the hook

SessionStart can't block. Exit-2 stderr shows to the user only (**H**).

**Timing** (**H**): interactive SessionStart hooks run in the background, and "Claude's first response still waits for the hooks to finish".

**Stop** (**H**):
- `{"decision":"block","reason":"…"}`: `reason` is required and "Tells Claude why it should continue".
- `hookSpecificOutput.additionalContext` also continues the turn, is labeled "Stop hook feedback", and shows no error notice. The same loop protections apply.

**PreToolUse** (**H**):
- `permissionDecision: "allow"` "skips the permission prompt", except for the actions no mode auto-approves, `AskUserQuestion`/`ExitPlanMode`, and (since v2.1.199) MCP tools marked `_meta["anthropic/requiresUserInteraction"]`.
- "Deny and ask rules are still evaluated regardless of what the hook returns."
- Precedence across hooks: deny > defer > ask > allow.
- `permissionDecisionReason` for allow is shown to the user, not Claude.
- The legacy `decision: approve|block` form is deprecated.

**Universal fields** (**H**):
- `systemMessage`: "Warning message shown to the user". In `--output-format stream-json` and the SDK it can arrive as `SDKInformationalMessage`. "Some events discard it", and each event's section says so (e.g. Setup, InstructionsLoaded, StopFailure).
- `suppressOutput`: "**Has no effect**: Claude Code accepts the field but doesn't act on it."
- `continue: false` + `stopReason`: stops processing entirely.

### A3. Async hooks

**Semantics** (**H**, CC-HOOKS "Run hooks in the background"):
- `"async": true` exists on **`type:"command"` only**.
- Async hooks "can't block or control Claude's behavior: `decision`, `permissionDecision`, `continue` have no effect".
- After exit, `additionalContext` and `systemMessage` are delivered **to Claude on the next conversation turn**. "Unlike a synchronous hook's systemMessage, neither field is shown to you."
- If the session is idle, delivery waits for the next user interaction.
- `timeout` is **not enforced** on async hooks.
- In `-p` mode, running async hooks are killed at teardown with outcome `cancelled`.
- There is no dedup across firings.

**Related** (**H**):
- `asyncRewake: true` runs in the background and wakes Claude on exit 2. Its timeout **is** enforced.
- Completion notices are hidden unless `--verbose` or Ctrl+O. This has been the default since 2.1.75.

**Version introduced: unknown.** The earliest changelog mention is 2.1.19/2.1.23 (Jan 2026: "Fixed pending async hooks not being cancelled when headless streaming sessions ended"), so async hooks predate 2.1.23 (**M**).

### A4. Registration, test isolation, timeouts

**Where hooks live** (**H**):
- `~/.claude/settings.json`, `.claude/settings.json`, `.claude/settings.local.json`, managed policy, plugin `hooks/hooks.json`, skill/agent frontmatter.
- Shape: `{"hooks":{"<Event>":[{"matcher":"…","hooks":[{"type":"command","command":"…","timeout":N,"async":bool,"args":[…]}]}]}}`.
- Hook entries **merge** across levels rather than override. The same handler defined in more than one settings file runs once.
- All matching hooks run in parallel.

**`args`** (**H**): the exec form. It spawns `command` directly with no shell, which avoids quoting issues.

**Test isolation** (**H**, CC-CLI and CC-SETTINGS):
- `--settings <file-or-json>` "applies it above your user, project, and local files and below managed settings". The file must be regular and 2 MiB or smaller. The docs' own example is `--settings '{"disableAllHooks": true}'`.
- `--setting-sources user,project,local` restricts which file sources load.
- The `CLAUDE_CONFIG_DIR` env var relocates `~/.claude` (settings, sessions, plugins).
- `--debug-file <path>` gives hook logs.
- `--bare` and `--safe-mode` skip hooks.

Inference (**M**): that hooks defined inside a `--settings` file are loaded and merged is implied by "any key your user settings file can set" plus hook merging. Pin it with a test.

**Timeouts** (**H**):
- Defaults: command/http/mcp_tool = **600 s**; prompt = 30 s; agent = 60 s.
- UserPromptSubmit and Pre/PostModelSwitch default to **30 s**.
- A timed-out UserPromptSubmit hook's output (including `additionalContext`) is **discarded**, and the prompt proceeds.
- A timed-out PreToolUse command hook does **not** block.

### A5. MCP matchers (**H**)

**Matcher rules**:
- A matcher with only letters, digits, `_`, `-`, space, `,`, `|` is an **exact** match, or a list of exact matches.
- Any other character makes it an **unanchored JS regex** (`RegExp.test`).
- `"*"`, `""`, or omitted matches all.

**Consequences**:
- `mcp__memory` (bare) matches **nothing**. Use `mcp__memory__.*`, or `^…$` to anchor.
- MCP tools are named `mcp__<server>__<tool>`.
- Plugin-bundled servers are named `mcp__plugin_<plugin-name>_<server-name>__<tool>`. For example, `mcp__plugin_my-plugin_db__query`. A bare-server matcher "never fires" for these.

## B. Codex CLI 0.148.0-alpha.21 (commit fecac1c)

### B1. Feature and configuration

**Feature flag** (**H**):
- `features.hooks`: `Feature::CodexHooks`, `Stage::Stable`, `default_enabled: true` (`features/src/lib.rs:95-96, 1017-1022`).
- The legacy alias is `codex_hooks` (`features/src/legacy.rs:48-51`). `cli/src/doctor.rs:3254` flags it as deprecated.

**Two representations per config layer** (`hooks/src/engine/discovery.rs:91-203`), **H**:
1. `hooks.json` in the layer's config folder. The user layer folder is `$CODEX_HOME` (default `~/.codex`), and the project folder is `<repo>/.codex/`. See `load_hooks_json` at `discovery.rs:336-377` and `config/src/state.rs:239-243`.
   - Top-level keys are only `description` and `hooks`, with `deny_unknown_fields` (`config/src/hook_config.rs:10-17`). A Claude `settings.json` with other keys will not parse.
2. A `[hooks]` table in `config.toml` (`discovery.rs:379-397`).
   - Using both in one layer produces a warning (`discovery.rs:151-163`).
   - The `[features]`/`-c` session-flags layer is also a source (`discovery.rs:418`).

**Handler shape** (`hook_config.rs:139-187`), **H**:
- Events → `[{matcher, hooks:[…]}]`.
- `type:"command"` takes `command`, `commandWindows`, `timeout` (seconds), `async`, `statusMessage`, and `additionalContextLimit` (tokens; default 2,500; `0` disables spilling).
- `type:"mcp_tool"` takes `server`, `tool`, `input`, `timeout`.
- `prompt` and `agent` hooks are skipped as "not supported yet" (`discovery.rs:638-657`).

**TRUST GATE: critical for tests** (**H**). Non-managed hooks run only if `enabled` **and** trust status is Managed/Trusted, **or** bypass is set (`discovery.rs:704-722`).
- Trust means `hooks.state."<key>".trusted_hash == sha256(canonical normalized hook)`.
  - Status logic: `discovery.rs:782-806`. Hash function: `config/src/fingerprint.rs:44-56`.
  - The key is `"<source_path>:<event_label>:<group_idx>:<handler_idx>"` (`hooks/src/lib.rs:92-119`).
  - State is read only from User and SessionFlags layers (`hooks/src/config_rules.rs:15-40`).
- The TUI shows "Hooks need review" and writes `hooks.state` through `config/batchWrite` (`tui/src/hooks_rpc.rs:57-85`, `tui/src/startup_hooks_review.rs:229`).
- The bypass is the CLI flag `--dangerously-bypass-hook-trust` (`utils/cli/src/shared_options.rs:61-64`). It is global on `codex exec` (`exec/src/cli.rs:140`).
- An untrusted hook in `codex exec` is silently not run. **M**: I found no exec warning path.

Other: `allow_managed_hooks_only` is honored only in `requirements.toml` (`docs/config.md:9-15`). Plugins can also bundle hooks (`discovery.rs:241`).

### B2. Events and stdin payloads

**Events** (`hook_config.rs:35-59`), **H**: PreToolUse, PermissionRequest, PostToolUse, PreCompact, PostCompact, SessionStart, SessionEnd, UserPromptSubmit, SubagentStart, SubagentStop, Stop. There is no Notification, StopFailure, etc.

**Payloads** (`hooks/src/schema.rs`, `deny_unknown_fields`), **H**:
- **SessionStart** (`schema.rs:483-497`): `session_id`, `transcript_path` (string|null), `cwd`, `hook_event_name`, `model`, `permission_mode` (`default|acceptEdits|plan|dontAsk|bypassPermissions`), `source`.
  - `source` is one of `startup|resume|clear|compact` (`hooks/src/events/session_start.rs:24-40`). There is **no** `fork`: forked sessions map to `startup` (`core/src/session/session.rs:1428-1434`).
  - Compaction queues `compact` (`core/src/session/mod.rs:3369`).
- **UserPromptSubmit** (`schema.rs:551-570`): common fields + `turn_id` (a Codex extension), optional `agent_id`/`agent_type`, `prompt`.
- **Stop** (`schema.rs:572-588`): common fields + `turn_id`, `stop_hook_active`, `last_assistant_message` (string|null).
- **PreToolUse** (`schema.rs:271-292`): common fields + `turn_id`, `tool_name`, `tool_input`, `tool_use_id`. It has no `mcp_server` field.
  - MCP `tool_name` = `mcp__<server>__<tool>` (`core/src/tools/handlers/mcp.rs:91-113`, test at `:546`).
  - Shell tools use `Bash`. `apply_patch` also matches the aliases `Write`/`Edit`, and `spawn_agent` matches `Agent` (`core/src/tools/hook_names.rs:34-56`).
- **PreCompact/PostCompact**: common fields + `turn_id` and `trigger` (`schema.rs:340-378`).

**Timing difference vs Claude** (**H**): SessionStart hooks are **queued and run at the start of the first turn**, before UserPromptSubmit, not at process launch (`core/src/session/session.rs:1449-1452`, `core/src/session/turn.rs:242-247`). They also re-run mid-turn after compaction (`turn.rs:475`).

### B3. Output handling

**Universal output** (`schema.rs:84-97`), **H**: `continue`, `stopReason`, `suppressOutput`, `systemMessage`, with `deny_unknown_fields`. **Any unknown key makes the JSON invalid.** Claude-only fields like `sessionTitle` or `terminalSequence` will fail parsing (**M**, from `deny_unknown_fields`).

**SessionStart / UserPromptSubmit** (`events/session_start.rs:242-310`, `events/user_prompt_submit.rs:158-225`), **H**:
- `hookSpecificOutput.additionalContext` is honored.
- Plain non-JSON stdout on exit 0 becomes additionalContext.
- JSON-looking but invalid output means the hook failed.
- Context is recorded as a **developer-role message** (`core/src/context/hook_additional_context.rs`, `core/src/hook_runtime.rs:680-698`).
- Over 2,500 tokens, the context spills to a file with a preview (`hooks/src/output_spill.rs:12`).
- UserPromptSubmit `decision:"block"`+`reason` or exit 2 (with stderr) stops the prompt.
- SessionStart `continue:false` stops. Its non-zero exits are just "failed".

**Visibility to the user: differs from Claude** (**H**):
- The TUI hook cell renders `systemMessage` as "`<label> (status) says: …`". It **also renders additionalContext as a "hook context:" preview** (`tui/src/history_cell/hook_cell.rs:459-497, 826-833`). Only a completed hook with zero entries is hidden (`:805-807`).
- `codex exec`, human output: HookCompleted prints only `hook: <Event> <Status>` to stderr. **systemMessage and context are not printed** (`exec/src/event_processor_with_human_output.rs:261-277`).
- `codex exec --json`: hook events are dropped entirely (`exec/src/event_processor_with_jsonl_output.rs:462`).
- Exception: an **async** hook's systemMessage becomes a `Warning` event (`core/src/hook_runtime.rs:633-642`). exec prints warnings (`event_processor_with_human_output.rs:241`).

**Stop** (`events/stop.rs:226-310`, `core/src/session/turn.rs:482-519`), **H**:
- `{"decision":"block","reason":"…"}` (the reason must be non-empty) or exit 2 + stderr: the reason is recorded as a **hook prompt message**, the turn continues, and `stop_hook_active` is set to true.
- A block without a prompt produces the warning "Stop hook requested continuation without a prompt; ignoring the block."
- Stop has **no additionalContext**. Plain-text stdout from a sync Stop hook is an **error**.
- **M**: I found no consecutive-continuation cap in `turn.rs`, so loop protection relies on the hook reading `stop_hook_active`.

**PreToolUse** (`hooks/src/engine/output_parser.rs:117-178, 428-469`), **H**:
- `permissionDecision:"allow"` **without** `updatedInput` is rejected: "PreToolUse hook returned unsupported permissionDecision:allow".
- `"ask"` is unsupported.
- `"allow"`+`updatedInput` only **rewrites input**.
- `"deny"`+reason blocks.
- `continue:false`, `stopReason`, and `suppressOutput` are all rejected.
- **PreToolUse cannot approve.** Approval is the **PermissionRequest** hook: `hookSpecificOutput.decision.behavior: "allow"|"deny"`. It runs first in `Session::request_approval`, including for MCP tool calls: "Approval precedence is: 1. Hooks 2. Guardian/user" (`core/src/tools/approvals.rs:483-515`, `schema.rs:183-221`).
- For debrief, this means auto-approving its own MCP tools needs a `PermissionRequest` hook in Codex and a `PreToolUse` hook in Claude.

**Matchers** (`events/common.rs:110-150, 163-171`), **H**:
- Exact match when the matcher has only `[A-Za-z0-9_|]`. A **hyphen, unlike Claude, forces regex**.
- Anything else is compiled as a Rust `regex` with unanchored `is_match`.
- `""` or `*` matches all.
- Matchers are ignored for UserPromptSubmit and Stop.

### B4. Async and timeouts

**Async** (`discovery.rs:528-534`, `engine/dispatcher.rs:101-110`, `engine/command_runner.rs:41, 99-159`, `core/src/hook_runtime.rs:604-646`), **H**:
- `async: true` exists on command hooks. SessionEnd async hooks run synchronously instead.
- At most 8 concurrent async hooks.
- Async hooks cannot apply control effects (`engine/mod.rs:96-99`).
- Their Context entries are drained at turn boundaries: before the user prompt they go into history, mid-turn they are injected into the running turn. Their warnings become Warning events.
- Pending results are dropped at shutdown (`core/src/session/handlers.rs:404-405`).

**Timeouts**, **H**:
- Default **600 s** for command and mcp_tool hooks (`discovery.rs:617, 739`).
- SessionEnd defaults to 1 s and is clamped to 3 s (`events/session_end.rs:20-23`).
- The timeout **is enforced for async hooks too**, since both paths use the same `run_command` (`command_runner.rs:267`).

### B5. `codex exec`

**Yes, hooks run in `codex exec`.** The upstream test `exec/tests/suite/hooks.rs:8-43` writes `$CODEX_HOME/hooks.json` with SessionStart and runs `codex exec --skip-git-repo-check --dangerously-bypass-hook-trust "…"`, then asserts the hook ran (**H**). Without bypass or a persisted `trusted_hash`, user and project hooks will not run in exec (**M**, from the trust gate).

## Design-relevant deltas (summary)

| Aspect | Claude Code 2.1.283 | Codex 0.148.0-alpha.21 |
|---|---|---|
| Config | settings.json `hooks` (merge across levels); `--settings` for tests | `$CODEX_HOME/hooks.json`, `.codex/hooks.json`, or `[hooks]` in config.toml |
| Trust | none beyond workspace trust | **per-hook sha256 trust** or `--dangerously-bypass-hook-trust` |
| SessionStart sources | startup/resume/clear/compact/**fork** | startup/resume/clear/compact (fork maps to startup) |
| SessionStart timing | at launch (background; first response waits) | lazily at first turn start |
| additionalContext visible to user | no (system reminder) | **yes in TUI** ("hook context:" preview); not in exec |
| systemMessage | shown to user (sync) | TUI yes; exec human no (only async becomes a Warning); exec --json no |
| Stop continue | `decision:block`+`reason`, or `additionalContext`; cap of 8 | `decision:block`+`reason` only; no cap found |
| Approve MCP tool | PreToolUse `permissionDecision:"allow"` | **PermissionRequest** `decision.behavior:"allow"` (PreToolUse allow is invalid) |
| Unknown output keys | tolerated (M) | **rejected** (`deny_unknown_fields`) |
| Async | command only; no timeout; output to Claude next turn; killed in `-p` | command only; timeout enforced; context drained at turn boundaries |
| Default timeout | 600 s (UserPromptSubmit 30 s) | 600 s (SessionEnd 1–3 s) |
| Exact matcher charset | `[A-Za-z0-9_\- ,|]` | `[A-Za-z0-9_|]` |
